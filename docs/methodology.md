# モデルと解析手法

## 1. プラントモデル

```
エンジン(J_e) ──クラッチ(容量 T_cap)── 変速機(i_g·i_f) ── 駆動軸(k, c) ── 車体(M)
```

状態量は 4 つ:エンジン角速度 `ω_e`、車輪角速度 `ω_w`、駆動軸ねじり角 `θ`、車速 `v`。
刻み 1 ms の semi-implicit Euler で積分します(`amtlab/simulation/plant.py`)。

### 運動方程式

エンジン側

$$J_e \dot{\omega}_e = T_e - T_c$$

車輪側(ギヤ締結時。ニュートラルでは `T_c = 0`)

$$J_{gw}\,\dot{\omega}_w = T_c\, i_g i_f\, \eta - T_{shaft},\qquad
J_{gw} = J_w + J_{in}\,(i_g i_f)^2$$

駆動軸(ねじり 2 慣性)

$$T_{shaft} = k\,\theta + c\left(\omega_w - \frac{v}{r_w}\right),\qquad
\dot{\theta} = \omega_w - \frac{v}{r_w}$$

車体

$$M\dot{v} = \frac{T_{shaft}}{r_w} - F_{road},\qquad
F_{road} = \tfrac12 \rho C_dA\,v|v| + M g \mu_r \tanh\!\left(\tfrac{v}{0.5}\right) + Mg\sin\phi$$

### クラッチのすべり/ロック

- 容量: `T_cap(x) = T_cap,max · ((x - x_kiss)/(1 - x_kiss))^1.6`(`x` はストローク比、ミート点以下は 0)
- **すべり中**: `T_c = T_cap · sign(ω_e - ω_in)`
- **ロック中**: 両側を剛結合として必要伝達トルクを解き、`|T_c| > T_cap` になったらすべりへ遷移

$$\dot{\omega}_w = \frac{T_e\,i\,\eta - T_{shaft}}{J_{gw} + J_e i^2 \eta},\qquad
T_c = T_e - J_e\, i\, \dot{\omega}_w$$

- すべり収束時(`|ω_e - ω_in| < 1.5 rad/s`)は角運動量を保存して締結します。

駆動軸剛性 `k = 4000 Nm/rad`、減衰 `c = 30 Nms/rad` は、実車で問題になる
**2〜8 Hz のシャッフル振動**(本モデルでは約 6.7 Hz)を再現するための値です。
これによりクラッチ再締結の速さがジャーク指標に効くようになります。

### エンジン

全開トルクマップの線形補間と、全閉時の引きずりトルク `-(10 + 0.008·rpm)` を
スロットル開度で内挿。トルク指令には時定数 60 ms の一次遅れを入れています。

## 2. 変速シーケンス(状態機械)

`amtlab/simulation/controller.py`。AMT は単板クラッチなので、以下を順に実行します。

| # | フェーズ | 内容 | 効く適合値 |
| --- | --- | --- | --- |
| 1 | `torque_reduce` | エンジントルクを落とす | `torque_reduce_rate` |
| 2 | `clutch_open` | クラッチ解放 | `clutch_open_rate` |
| 3 | `gear_out` | ギヤ抜き(ニュートラル) | — |
| 4 | `speed_sync` | エンジン回転を締結先へ同期(アップ=引きずり、ダウン=空吹かし) | `sync_gain`, `sync_slip_offset` |
| 5 | `gear_in` | ギヤ入れ | — |
| 6 | `clutch_close` | ミート点まで早戻し → 締結 | `kiss_approach_rate`, `clutch_close_rate` |
| 7 | `torque_recovery` | ドライバ要求トルクへ復帰 | `torque_recovery_slip`, `torque_recovery_rate` |

3〜5 の間は駆動トルクがゼロ = **トルクホール**。各フェーズにはタイムアウトを設け、
異常な適合値でもシミュレーションが発散・無限ループしないようにしています
(打ち切られた場合 `completed = 0` となり目的関数でペナルティを受けます)。

適合パラメータの探索範囲は `amtlab.simulation.controller.CONTROL_BOUNDS` に集約しており、
DoE のサンプリングと Optuna の探索空間の両方がここを参照します。

## 3. 変速品質 KPI

`amtlab/features.py`。評価窓は「変速指令 〜 変速完了 + 0.6 s」。
**変速時間と車速の落ち込み**を主指標に置き、他はその裏付け・副作用の監視に使う。

| KPI | 定義 |
| --- | --- |
| `shift_time_s` | 変速指令からトルク復帰完了まで |
| `speed_drop_kmh` | **車速の落ち込み幅**。評価窓内のピーク → 谷 |
| `speed_drop_pct` | 同上をピーク車速に対する % で表したもの |
| `speed_loss_kmh` | **変速による車速損失**。変速前加速度を延長した「変速しなかった場合」との最大差 |
| `speed_recovery_s` | 谷から落ち込み前のピーク車速へ戻るまでの時間(窓内で戻らなければ NaN) |
| `torque_interrupt_s` | 駆動軸トルクが変速前の 20% を下回る時間 |
| `jerk_rms`, `jerk_peak` | 加速度(10 Hz ゼロ位相ローパス)の時間微分の RMS / 最大 |
| `accel_drop` | 変速前加速度からの落ち込み量 |
| `clutch_energy_j` | `∫ \|T_c · Δω\| dt`(すべり仕事) |
| `engine_flare_rpm` | 変速中のエンジン回転が「開始回転 or 同期先回転」を超えた量 |
| `current_gear` | カレントギア(= 変速前の段 `from_gear`) |
| `quality_score` | 目的 KPI を正規化した重み付き和(小さいほど良い) |

### 3.1 車速の落ち込みを 2 通りで測る理由

同じ「落ち込み」でも、運転条件によって意味が変わる。

- **低速段・大トルクの全開アップシフト**: トルクが抜けても走行抵抗が小さいので
  車速は落ちない。落ちないが「伸びが止まる」。→ ピーク→谷の落ち込みは **0**
- **高速段・低負荷や惰行中**: 走行抵抗が大きく、実際に車速が落ちる。
  ただし惰行中は変速しなくても落ちる。→ ピーク→谷は **変速の責任ではない分を含む**

そこで両方を持つ。`speed_drop_kmh` は**波形からそのまま読める実測量**、
`speed_loss_kmh` は**変速そのものが奪った車速**である。

DoE 400 イベントでの実測(本モデル):

| 指標 | 変速時間との相関 | ほぼ 0 になる割合 |
| --- | --- | --- |
| `speed_drop_kmh` | 0.24 | 36 %(全開アップシフトで頻発) |
| `speed_loss_kmh` | 0.53 | 0 % |

### 3.2 目的関数に使うのはどちらか

**`speed_loss_kmh` を使う。** 理由は `speed_drop_kmh` が単調でないため。
代表条件でベースラインと「わざと遅くした適合値」を比較すると:

| 条件 | 変速時間 [s] | `speed_drop_kmh` | `speed_loss_kmh` |
| --- | --- | --- | --- |
| 1→2 @18 km/h, 85% (基準) | 1.22 | 0.00 | 15.35 |
| 1→2 @18 km/h, 85% (低速適合) | 2.72 | 0.00 | 30.27 |
| 2→3 @42 km/h, 60% (基準) | 1.10 | 0.51 | 6.22 |
| 2→3 @42 km/h, 60% (低速適合) | 2.35 | **0.00** | 11.66 |

変速を 2 倍遅くしたのに `speed_drop_kmh` は 0.51 → 0.00 と「改善」してしまう
(トルクが抜けている間も加速し続けるため谷が消える)。これを最小化すると
最適化が誤った方向に進む。一方 `speed_loss_kmh` は 6.22 → 11.66 と正しく悪化する。

`speed_drop_kmh` は記述指標として全ての表・図・レポートに併記しており、
目的 KPI は `configs/*.yaml` の `calibration.objectives` で差し替えられる。

### 3.3 カレントギア(現在ギア)別の集計

`from_gear` = カレントギア(変速前の段)、`to_gear` = 変速先。
:func:`amtlab.features.gear_summary` がカレントギア × 変速方向で KPI を集計する。
本モデルでは 2 つの指標がギヤに対して**逆方向**の傾向を示す。

- `speed_loss_kmh`: 低速段ほど大きい(1速 7.2 → 5速 1.6 km/h)。駆動力が大きいほど
  トルクが抜けたときの損失も大きい
- `speed_drop_kmh`: 高速段ほど大きい(1速 1.3 → 5速 2.1 km/h)。走行抵抗が
  大きい高車速ほど実際に車速が落ちる

「1速→2速が最悪」と言えるのは損失で見たときであり、波形の落ち込み幅だけを
見ていると見落とす。

## 4. データ生成(DoE)

`amtlab/dataset.py` はランダム DoE で「運転条件 × 適合値」を一様サンプリングします。

- 運転条件: 変速段組(隣接段のみ)、車速(エンジン回転が実用域に入るよう逆算)、
  スロットル、勾配 −6〜+8 %、積載 0〜400 kg
- 適合値: `CONTROL_BOUNDS` の一様乱数

1 行 = 1 変速イベント。joblib で並列実行し、600 イベントで数十秒です。

## 5. 代理モデルと感度解析

`amtlab/modeling.py` / `amtlab/tuning.py`。

- 前処理: ギヤ段は One-Hot、連続量は標準化(`ColumnTransformer`)
- モデル: `HistGradientBoosting` / `RandomForest` / `ExtraTrees` / `RidgeCV`
- 評価: 5-fold CV の OOF 予測で RMSE・MAE・R²
- **Optuna(TPE)がモデル種別ごとハイパーパラメータを探索**し、CV RMSE を最小化
- 感度解析: permutation importance(R² 低下量)と部分依存(PDP)
- `condition_only_baseline` は「運転条件だけで説明した場合」の R² を出し、
  **適合値がどれだけ説明力を足しているか**を切り分けます

## 6. 適合最適化

`amtlab/calibration.py`。代表運転条件 7 点(低速段の大トルク変速、登坂 + 積載、
ダウンシフトを含む)に対して 1 組の適合値を評価します。

- 集約: 条件平均と最悪条件を `worst_case_weight`(既定 0.3)でブレンド
  → **どの条件でも破綻しない適合値**を要求する
- 目的(既定): **`shift_time_s`(変速時間)・`speed_loss_kmh`(車速損失)・
  `jerk_rms`(変速ショック)**。前 2 つが主目的、ジャークは速さを追い過ぎない抑え役
- `scalar` モード: TPE で重み付きスカラー目的を最小化
- `pareto` モード: NSGA-II で多目的最適化し、パレート解の中から重み付き最良解を選ぶ
- 目的に入れない `speed_drop_kmh` / `jerk_peak` / `clutch_energy_j` /
  `torque_interrupt_s` は監視 KPI として毎試行記録し、改善表に必ず併記する
- `use_surrogate: true` にすると評価を代理モデル予測で行い高速化。
  ただし **最終的な best/baseline の指標は必ずシミュレーションで再評価**します。

## 7. 実車ログの取り込み(J1939)

`amtlab/j1939.py` と `amtlab/ingest.py`。

### 7.1 使用する SPN

| SPN | PGN | 信号 | 何に効くか |
| --- | --- | --- | --- |
| 574 | ETC1 | Transmission Shift In Process | **変速イベントを推定でなく直接切り出す** |
| 523 | ETC2 | Transmission Current Gear | カレントギア(変速前の段) |
| 524 | ETC2 | Transmission Selected Gear | 変速先ギヤ(ニュートラル中でも確定) |
| 526 | ETC2 | Transmission Actual Gear Ratio | ニュートラル判定(比 0)・同期先回転の算出 |
| 161 | ETC1 | Transmission Input Shaft Speed | クラッチすべりの実測 |
| 191 | ETC1 | Transmission Output Shaft Speed | 変速機出力回転(同期の基準) |
| 522 | ETC1 | Percent Clutch Slip | **締結完了時刻の実測** |
| 190 | EEC1 | Engine Speed | 回転同期・吹け上がり |
| 512 | EEC1 | Driver's Demand Engine - Percent Torque | トルク復帰の目標値 |
| 513 | EEC1 | Actual Engine - Percent Torque | トルクダウン/復帰の実測 |
| 514 | EEC1 | Nominal Friction - Percent Torque | 正味トルクへの補正(あれば自動使用) |
| 544 | EC1 | Engine Reference Torque | % → Nm 換算の基準 |
| 91 | EEC2 | Accelerator Pedal Position 1 | 運転条件(負荷) |
| 84 | CCVS1 | Wheel-Based Vehicle Speed | 車速の落ち込み |
| 904 | EBC2 | Front Axle Speed | 車速(非駆動輪なら車体速度の代用に最適) |

列名はロガーによって変わるため、SPN 番号・英語名・日本語名の別名パターンで
自動検出する(`amtlab.j1939.detect_columns`)。`amtlab inspect --log` で
何が検出できたかを確認できる。

### 7.2 変速イベントの切り出し

優先順位は次の通り。

1. **SPN 574 の立ち上がり/立ち下がり**(推奨)
   変速開始 = フラグ立ち上がり(トルクダウン開始を含む)、
   ギヤ入り = フラグ立ち下がり。
2. ギヤ信号(SPN 523)の遷移。ニュートラル経由に対応するが、
   トルクダウンの区間を捉えられないぶん変速時間が短く出る。

締結完了(= 変速時間の終端)は次の順で判定する。

1. クラッチ滑り率(SPN 522)が 1% を切った時刻
2. エンジン回転(190) と インプットシャフト回転(161) の一致
3. エンジン回転 と アウトプットシャフト回転(191) × 実ギヤ比(526) の一致
4. 車速から換算した入力軸回転との一致(信号が無い場合のみ)

これにより変速時間が

    変速時間 = ギヤ入りまで(gear_engage_time_s) + クラッチ締結(clutch_close_time_s)

に分解され、遅れがトルク相にあるのか締結相にあるのかを切り分けられる。

### 7.3 トルクホールの実測

J1939 のトルクは参照トルクに対する % なので、

    エンジントルク [Nm] = (SPN 513 − SPN 514) × SPN 544 / 100
    駆動側トルク [Nm]   = エンジントルク × SPN 526(実ギヤ比)

として `torque_interrupt_s` を実測から出す。SPN 512(要求トルク)があれば、
実トルクが要求の 90% に戻るまでの `torque_recovery_s` も測れる。

### 7.4 ジャークは J1939 だけでは測れない

ここが実務上いちばん重要な制約。

- 車速(SPN 84)は **10 Hz** 程度でしか更新されない。階段状の信号を微分すると、
  量子化が偽のジャークとして出る(実測: 10 Hz ホールドの等加速度信号を
  10 Hz ローパスで微分すると、本来 0 のジャークが RMS 39 m/s³ になる)。
  そこで **ローパス周波数を実効レートの 1/3 に自動で下げる**。
- アウトプットシャフト回転(SPN 191)は 50 Hz で来るので一見good だが、
  **これは駆動側の速度**であって車体速度ではない。駆動軸のねじり振動が
  そのまま乗るため、微分すると乗り心地ではなくシャッフル振動を測ってしまう
  (デモログでピークジャークが 777 m/s³ という非物理な値になる)。
  よって加速度の算出には使わず、`driveline_speed_kmh` として
  振動観察用にだけ保持する。
- 前輪速度(SPN 904)は、前輪が非駆動輪であれば駆動系のねじりを含まない
  車体速度の代用になる。車速より高レート(20 Hz)で車速と 2% 以内で
  一致する場合に限り自動で採用する。

結論として、この信号セットで**定量評価できるのは変速時間・車速の落ち込み・
トルク抜け**であり、ジャークを定量指標にするには車体前後加速度(50 Hz 以上)
の追加計測が要る。各イベントの `jerk_quality` 列に
`measured` / `derived` / `low_rate` / `unusable` を記録する。

| 指標 | J1939 のみ | 加速度センサ追加 |
| --- | --- | --- |
| 変速時間・分解(トルク相/締結相) | ◎ 実測 | ◎ |
| 車速の落ち込み・車速損失 | ◎ 実測 | ◎ |
| トルク抜け時間・トルク復帰時間 | ◎ 実測 | ◎ |
| クラッチすべり時間 | ◎ 実測(SPN 522) | ◎ |
| 吹け上がり | ◎ 実測(191 × 526) | ◎ |
| ジャーク(乗り心地) | △ 参考値 | ◎ |

## 8. モデルの限界

本モデルは適合の**トレードオフ構造を再現する**ことを目的とした簡易モデルです。
実車適合に用いる場合は、少なくとも次の同定・拡張が必要です。

- クラッチ容量特性(温度・摩耗依存)とアクチュエータ応答の実測同定
- 駆動軸剛性・減衰、エンジンマウント剛性の同定(シャッフル周波数の合わせ込み)
- タイヤすべり、ブレーキ、勾配推定誤差
- 変速線(いつ変速するか)の最適化は本モデルの対象外(ここでは「どう変速するか」のみ)
